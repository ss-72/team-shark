# 自動生成機能 補足資料

> 作成日: 2026-09-01 (更新日: 2026-09-04)  
> 上位仕様: `docs/PROJECT_PLAN.md`

## 結論

チームB引き継ぎタスクにより、時間割の自動生成エンジン、HTTP 422不足理由返却、ロールバック保護、教員本人用時間割API/画面、および自動テスト基盤が**完成**した。

## 実装内容

- `POST /api/timetables/generate`
  - バックトラック探索による制約遵守（担当可能科目、出勤不可日時、教員・教室衝突防止、並行授業対応）
  - 必要コマ数の完全一致保証（`assigned == required`）
  - 生成不能時の HTTP 422 Unprocessable Entity および科目別不足理由（`shortages`）返却
  - メモリ上での候補検証、および置換保存時のトランザクション保護（生成不能・保存失敗時の直前時間割維持）
- 時間割管理画面（`frontend/pages/timetables.html`, `frontend/js/timetables.js`, `frontend/js/timetable_view.js`）
  - 自動生成説明文の現行仕様化（「条件を満たす時間割を生成し、成功した場合のみ現在の時間割を置き換えます」）
  - 生成成功時の科目別割当コマ数表示
  - 生成不能時の 422 不足理由（必要・割当・不足・理由）の詳細表示
  - 週間カレンダーでの科目名・教員名・教室名表示（並行授業対応）
- 教員本人用時間割（`GET /api/my/timetable`, `frontend/pages/my_timetable.html`, `frontend/js/my_timetable.js`）
  - ログイン教員本人の割当時間割（曜日・時限・科目・割当教室）の確認
  - 他教員データとの完全分離（セッションの `user.teacher_id` のみ参照、パラメータ偽装無効化）
  - ログイン画面での role 別遷移（admin → 管理画面、teacher → 自分の時間割画面）
- 自動テスト（`backend/tests/test_team_b_generator.py`）
  - 要件A〜Jの網羅的自動テスト（app_context対応、admin認証、ロールバック検証、本人分離検証）

## 現行仕様との適合状況

| 項目 | 状態 | 実装状況 |
|---|---|---|
| 生成成功 | ✅ 完成 | 科目ごとの必要コマ数と生成件数が厳密に一致する（`assigned == required`） |
| 生成不能 | ✅ 完成 | HTTP 422 と科目別の不足理由（`subject_id`, `subject_name`, `required`, `assigned`, `missing`, `reason`）を返す |
| 既存時間割 | ✅ 完成 | 生成不能・保存失敗時は直前の時間割が完全に保持される（トランザクションとrollback） |
| 結果表示 | ✅ 完成 | 成功件数・科目別充足数、および生成不能時の不足理由を画面表示する |
| テスト | ✅ 完成 | 正常系・NG時間・重複・並行授業・生成不能422・既存データ保持・ロールバック・本人時間割を自動テスト済み |
| 本人時間割 | ✅ 完成 | `GET /api/my/timetable` および教員用時間割画面（`pages/my_timetable.html`）を完備 |

## 注意点

- バックトラック探索はデータ量・制約数が増えると計算時間が増えるため、実運用でコマ数・制約が極端に増加した場合は探索打ち切りやヒューリスティック追加の検討を行う。
