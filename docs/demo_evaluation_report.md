## 4. デモを見せる前に「最低限」直すべき致命的なエラー
以下の1点は、そのまま実行すると**バックエンドが起動しない、もしくは接続エラーになる**ため、デモ前に必ず修正してください。

1. **データベース接続設定がMySQLの直書きになっている（致命的）**
   - **原因**: `backend/app.py` の20行目で `app.config['SQLALCHEMY_DATABASE_URI'] = 'mysql+pymysql://scrum_user:password123@localhost/school_db'` と直書きされています。デモ用PCにMySQLの環境と該当ユーザーがないと起動・接続エラーになります。
   - **修正方法**: 手軽なデモ用と割り切って、一時的に **SQLite** を使うように書き換えるのが一番安全です。
     ```python
     # app.py 20行目を以下に変更
     app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///school.db'
     ```

2. **（推奨）画面が「空っぽ」問題**
   - **原因**: `app.py` で起動時に `TimeSlot`（時限データ）の初期化は行っていますが、「教員」と「教室」の初期データがありません。
   - **対策**: エラーではありませんが、デモを始める際に画面が空っぽになるため、事前に手動で数件登録しておくか、デモのシナリオ内で「登録して見せる」手順を踏む必要があります。

## 5. 提案：デモをスムーズに見せるためのハッピーパス（操作手順）
画面が空っぽの状態からでも自然に見せられる、エラーを踏まない理想的なデモシナリオです。

1. **【教員管理画面】を開く**
   - 長崎さんの目の前で「山田先生（国語）」「田中先生（数学）」などを2〜3名サクサクと登録し、一覧に即座に反映される様子（非同期通信の滑らかさ）を見せる。
   - **同じ名前を入力して「重複エラーが出る」デモを挟むと、バリデーションが効いていることをアピールできる**。
2. **【教室管理画面】を開く**
   - 同様に「101教室」「理科室」などを登録し、データが蓄積されていく様子を見せる。
3. **【時間割管理画面】を開く**
   - **手動登録のデモ**: 新規登録フォームを開き、「先ほど登録した山田先生と101教室が、プルダウンからすぐに選べるようになっています」と見せながら、月曜1限に登録する。
   - **重複チェックのデモ**: 同じ枠に別の教員を割り当てようとして「教室が使用済み」エラーが出る様子を見せても良い。
   - **目玉機能（自動生成）のデモ**: 最後に「でも、これを全部手動でやるのは大変ですよね？」と前振りをしてから、**「⚡ 自動生成を実行」** ボタンをクリック。残りの枠が一気に埋まって時間割が生成される様子を見せる。
   - **週間カレンダーのデモ**: 生成結果がカレンダー形式で表示されるので、「教員別表示」ボタンで特定の教員の時間割に切り替えて見せると印象アップ。
